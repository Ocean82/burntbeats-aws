# Burnt Beats Premium UI / UX

Govern frontend work for a **professional audio + MIDI web product**. Output must feel art-directed, musically literate, and subscription-worthy — not generic AI UI or a sparse indie dashboard.

**Full specification:** [reference.md](reference.md) (read when implementing non-trivial UI, MIDI/DAW surfaces, or conversion flows).

## Prime directive

Act as senior product designer + frontend architect + creative-software interaction designer + conversion-aware SaaS strategist.

Deliver: premium, deliberate, audio-domain-aware, commercially intentional, handcrafted surfaces.

Avoid: side-project dashboards, untouched default shadcn, card-grid templates, neon overload, hobbyist sparsity, obvious autogenerated UI.

## Scope boundaries (default)

**Do** enhance visual quality, interactions, consistency, discoverability, and layouts inside the current app structure.

**Do not** unless explicitly asked: replace frontend stack, migrate routing, invent a design system that forces rewrites, merge waveform + MIDI into one mega-editor, re-architect services/APIs, rename broad concepts, add GPU/CUDA/WebGPU/Metal paths, or speculative infra changes.

**Deliberate vagueness:** Be specific on quality and surface identity; stay flexible on file structure so changes stay incremental.

## Hard constraints

| Area | Constraint |
|------|------------|
| Frontend | React 19 + TypeScript; Vitest + Playwright |
| Backend | Express orchestration; Python `stem_service` + boto3; S3 presign/proxy |
| Processing | **CPU-only** stem separation — strong async/progress UX, not fake instant GPU |
| Demucs/MDX | Align with existing `prefer_speed` / `quality_mode` expectations |

## Two creative surfaces (route every task)

| Surface | Optimized for | Primary UI |
|---------|---------------|------------|
| **A — Stem / waveform** | upload → process → preview → mix → export | waveforms, stem lanes, mixer, job progress, plan usage |
| **B — MIDI / DAW** | convert → edit notes → arrange → export | piano roll, transport, track list, velocity lanes, inspector |

**Shared:** typography, spacing rhythm, color principles, shell/nav, interaction polish, state messaging.

**Distinct:** controls, panel structure, editing metaphors, primary canvas — siblings, not clones.

## Visual system (summary)

- **Direction:** premium SaaS creative software; boutique pro-audio; dark-first layered neutrals; one brand primary + one active accent; semantic states; stable per-stem/track colors.
- **Typography:** Inter Variable (or equivalent) + tabular numerals for timecodes, BPM, dB, MIDI values; compact professional labels.
- **Layout:** 4px grid; tight professional density; 3–4 elevation planes (canvas → panel → float → modal).
- **Motion:** 100–150ms micro, 200–250ms panels, 300ms expand only when needed; respect `prefers-reduced-motion`.
- **Anti-generic:** hierarchy over same-radius monotony; depth without glow/glass crutches; DAW-realistic control density.

## Surface A checklist (waveform / stems)

Required affordances where applicable: dropzone, queue/job/progress states, waveforms, stem list/lanes, mute/solo/gain, transport, export, plan/usage signals, retry/reprocess.

Waveform UX: seek/scrub, zoom/pan, selection/loop regions, ruler, time display, comparative listening.

Mixer: real-tool track headers, compact gain, clear mute/solo states, meters when available — not form-like strips.

CPU async: explicit queue/processing/finalizing; never frozen screens; optimistic layout while outputs pending.

## Surface B checklist (MIDI / DAW)

Layout model: transport bar → piano roll canvas → track sidebar → lower lanes/inspector → optional right inspector; tools off the note canvas.

Piano roll: keyboard, bar/beat ruler, subdivisions, playhead, loop/selection, snap feedback, track-colored notes with strong selection states.

Tools (where scope allows): select, pencil, erase, split, box/lasso multi-select, move/resize notes, copy/paste, nudge, undo/redo.

Transport: play/pause/stop/loop, position readout, BPM/metronome when supported; playback tied to roll.

Minimum polish: velocity lane or equivalent — not an afterthought.

Optional if codebase-ready: ghost notes, scale overlay, drum lanes, region clips — never mandatory refactors.

## Subscription / conversion

- Time-to-value: waveform = hear separation fast; MIDI = see/edit notes fast.
- Upgrades at success moments and natural limits — not random interrupts.
- Frame premium as quality, speed, capacity, friction reduction, creator seriousness.
- Trust: reliable processing states, mature file handling, paid-product finish.

## Implementation workflow

1. Classify task: Surface A, Surface B, or shared shell.
2. Read existing components/routes; match conventions; minimal diff scope.
3. Define the **one** primary user action for this change.
4. Fix layout, hierarchy, and interaction clarity first.
5. Apply visual polish, density, and pro-audio control treatment second.
6. Add loading, empty, error, success, and CPU-progress states.
7. Run quality gate (below).
8. Stop before rewiring unrelated systems.

## Quality gate (before done)

- [ ] Correct surface identity (A vs B), not a generic dashboard
- [ ] No generic-template / default-shadcn artifacts
- [ ] Consistent spacing, radii, typography, elevation
- [ ] Tabular numerals on musical/time values
- [ ] Accessible focus, labels on icon controls, contrast, reduced motion
- [ ] Responsive under waveform render, piano roll edit, polling, large stem sets
- [ ] CPU jobs feel intentional (progress/orientation), not broken
- [ ] Feels expensive, intentional, and team-built at a glance

## Related skills

- Generic distinctive UI craft: `.github/skills/frontend-design/` or `impeccable` — **Burnt Beats product rules in this skill win** for this repo's audio/MIDI surfaces.
- Do not let generic skills override: two-surface model, CPU-only processing, or no-broad-refactor default.

## Final instruction

Do not ship UI that is merely "modern." Ship UI that feels expensive, musically literate, operationally mature, and difficult to distinguish from a funded product team's shipped work.
